## Differentiated workflow to deliver

The intended differentiation is the integrated **execution contract → portable state → independent verification → recoverable continuation** workflow in an existing coding assistant. Its value must be demonstrated by reproducible behavior: a second client reads the same unfinished state; a failing approved command prevents verified completion; an interrupted lease can be recovered without duplicate completion. It is not a claim that contracts, memory, handoffs, task queues, or verification were invented here.

The first release intentionally uses one local SQLite database, focused MCP tools, and a CLI. It avoids a hosted control plane, mandatory provider accounts, generalized multi-machine scheduling, and automatic merging. Portable JSON schemas offer an interoperability seam; upstream-specific importers are deferred until concrete workflows justify them.

## Observed local integration environment

During development, `codex --version` reported **codex-cli 0.160.0**. Read-only inspection confirmed `exec --json`, `--sandbox read-only`, `--cd`, and login-status support; `codex login status` reported authenticated. Claude Code was absent from `PATH`. No live model request was needed for these checks. Automated tests use fixture configuration directories and deterministic subprocesses; they do not edit developer account settings. Consult the release validation notes for any later explicitly authorized live run.

Native client UI discovery and model-driven tool invocation are distinct from an MCP protocol smoke test. Configuration tests and an official-SDK stdio client establish server wiring and tool behavior; they do not establish that both native client UIs were exercised.

Follow-up native validation on 2026-10-19: Codex 0.160.0 successfully listed and retrieved ProofRelay's generated project MCP configuration using `codex mcp list --json` and `codex mcp get proofrelay --json` in an isolated temporary configuration home. The expected stdio transport and arguments were returned. No server or model was launched, and real client settings were untouched. See the [Codex integration guide](integrations/codex.md) for the reproducible optional check.
